Lessons about specific weakness classes (from public CWE and OWASP guidance):
- Path traversal (CWE-22): normalising a joined path does not make it safe on its own. A containment check must compare whole path components; a plain string prefix check also accepts sibling directories whose names start with the base name. Absolute user paths can replace the base directory entirely in a join.
- SQL injection (CWE-89): values that were stored safely with parameters can still be unsafe when read back and later concatenated into another query (second-order injection). Identifiers such as column or sort names cannot be parameterised and need an allow-list.
- OS command injection (CWE-78): any shell invocation built from a string is dangerous when part of the string comes from users; quoting with plain double quotes still allows command substitution, and character blocklists usually miss some metacharacters. Argument lists without a shell avoid the problem.
- Unsafe deserialization (CWE-502): deserializing attacker-controlled bytes with formats such as pickle executes code during loading, so an integrity or signature check must happen before deserialization, never after it.
- Cross-site scripting (CWE-79): escaping must match the output context. Text that is safe inside an element body is not necessarily safe inside an attribute value; quotes must be escaped in attributes, and URL attributes also need a scheme check.
